## Description

This blueprint provides universal support for running any custom action when a button is pressed on the provided IKEA E2001/E2002/E2313 STYRBAR Remote control. Supports controllers integrated with Zigbee2MQTT, ZHA, deCONZ. The blueprint will automagically detect the integration type and take care of all the rest.

In addition of being able to provide custom actions for every kind of button press supported by the remote, the blueprint allows to loop the long press actions while the corresponding button is being held. Once released, the loop stops. This is useful when holding down a button should result in a continuous action (such as lowering the volume of a media player, or controlling a light brightness).

The blueprint also adds support for virtual double button press events, which are not exposed by the controller device itself. However, It needs to be enabled in the blueprint.

:::tip
Automations created with this blueprint can be connected with one or more [Hooks](/docs/blueprints/hooks) supported by this controller.
Hooks allow to easily create controller-based automations for interacting with lights, media players, covers and maybe more in the future. See the list of [Hooks available for this controller](#available-hooks) for additional details.
:::

## Additional Notes

### Helper - Last Controller Event

The `helper_last_controller_event` (Helper - Last Controller Event) input serves as a permanent storage area for the automation. The stored info is used to implement the blueprint's core functionality. To learn more about the helper, how it's used and why it's required, you can read the dedicated section in the [Controllers-Hooks Ecosystem documentation](/docs/controllers-hooks-ecosystem#helper---last-controller-event-input).

The helper is used to determine button release events when the controller is integrated with Zigbee2MQTT or ZHA, because of the actions mapping for the controller with these integrations. Natively, the controller doesn't allow to distinguish between different button release events for some of it's buttons, so the blueprint must store the previous clicked button.

### Virtual double press events

It's also important to note that the controller doesn't natively support double press events. Instead , this blueprint provides virtual double press events. You can read more about them in the [general Controllers-Hooks Ecosystem documentation](/docs/controllers-hooks-ecosystem#virtual-events).

### Issues with Zigbee2MQTT and the device firing duplicate events

It has been reported that IKEA E2001/E2002/E2313 controllers integrated with Zigbee2MQTT might fire duplicate events from time to time, during interaction. This issue is not relative to the blueprint itself.

If you notice your controller is not behaving as expected please reset the device and repeat the pairing process with Zigbee2MQTT, then try again.

### ZHA: a Left/Right long press also runs the Up button short press

**In short:** use version 2026.11.22 or later and leave **(ZHA) Helper - Ignore Up press after Left/Right release** at its default of 700 milliseconds. Do not lower it.

This note only applies when the controller is integrated with ZHA. Zigbee2MQTT and deCONZ are not affected.

#### Settings to use

| Input                                                   | Value to use         | Why                                                                                                     |
| ------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------- |
| (ZHA) Helper - Ignore Up press after Left/Right release | 700 (default)        | Values below about 510 let the Up button short press through. Use 550 or more. 0 turns the feature off. |
| Helper - Debounce delay                                 | 0 (default)          | Must stay below 400, otherwise the Left/Right event is recorded too late.                               |
| Helper - Last Controller Event                          | An Input Text helper | Required. The blueprint uses it to remember the Left/Right event.                                       |

#### What you will notice

- A Left/Right long press runs only the long press action and, when you let go, the release action. The Up button short press no longer runs with it.
- A real Up press is ignored if it comes within 0.7 seconds after you start or end a Left/Right long press. At any other time the Up button works normally, with no added delay.
- The remote itself needs about 2 seconds of holding before it reports a Left/Right long press. This cannot be shortened.

#### Why this happens

When a Left or Right button is held, the remote sends more than the long press. Measured on firmware 2.4.16 (`0x02040016`):

| Event from the remote | Time            | Meaning                                             |
| --------------------- | --------------- | --------------------------------------------------- |
| `release`             | 0 ms            | Sent as soon as the button is held                  |
| `on`                  | about 500 ms    | The same event the Up button sends on a short press |
| `hold`                | about 2000 ms   | The actual Left/Right long press                    |
| `release`             | when you let go | End of the long press                               |

The remote sends the `on` on purpose, so that an IKEA light is switched on before its colour is changed. It cannot be told apart from a real Up press, so the blueprint ignores an `on` that arrives shortly after a Left/Right `release`. Zigbee2MQTT does the same for this remote, with the same 700 milliseconds. Since the `on` arrives after about 500 milliseconds, a lower value lets it through.

#### Still seeing the Up action?

1. Check that the automation uses version 2026.11.22 or later of this release.
2. Set **(ZHA) Helper - Ignore Up press after Left/Right release** back to 700.
3. Set **Helper - Debounce delay** to 0.
4. Check that **Helper - Last Controller Event** points to an Input Text helper that no other automation uses.
5. If it still happens, open an issue and include the `zha_event` events of one Left/Right long press (Developer Tools, Events, listen to `zha_event`).
